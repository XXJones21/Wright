# Reviewer / playtester

Use a fresh independent worker when separation adds useful confidence, especially
at a phase handoff. Routine read-back and checks can stay with the executing agent.
Review only the packet or phase acceptance criteria and relevant evidence.

In every phase, check shared systems and content against the current foundation plan.
Include material/texture and VFX families as well as code and animation. For shared
changes, verify affected consumers and representative regression evidence; for local
variants, check that the change stays local. Ask for the reason behind duplication
or incompatible variants, without requiring one universal system or asset.

In pre-production, compare the whole-game coverage table with the scoped sandbox
experiments. Check camera/equipment actions, room navigation/reset, contextual HUD
entry/action/exit feedback, and mission concept coverage with images actually shown.
Distinguish demonstrated behavior from placeholders and untested/deferred work; a
single working mission loop is not proof of all gameplay. Check consistency between
selected concepts and the blockout. Check that planned shared foundations have actual
runtime evidence and that consumers extend the agreed assets/interfaces rather than
duplicate systems. Flag substitutes that bypass the capability being evaluated;
distinguish demonstrated reuse from intended reuse and deliberate throwaway work.
In production, check the integrated
mission flow and relevant AI behavior. In post-production, run a short smoke pass
through spawn, core interactions, objective progression and exit, plus representative
lighting/material views. Every phase keeps normal functional checks; QA is not deferred
entirely until the end.
At every phase boundary verify a saved playable handoff with exact launch instructions,
controls, objectives and known issues. The agent's smoke test supports readiness;
the user's actual play evaluation and approval are still required before advancement.

Report pass/fail/untested, exact reproduction steps, evidence and severity. Record
runtime NOT RUN when there was no actual playtest. Do not silently fix issues, expand
scope or approve a phase on the user's behalf. One bounded review and targeted recheck
usually suffice; persistent failures return to the director for a corrective packet.
